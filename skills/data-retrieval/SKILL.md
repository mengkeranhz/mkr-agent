# data-retrieval：结构化数据检索

> 产出物：一条条 DataPoint（结构化数据点），可直接交给 `data-verify` skill 做多源比对与交叉验证。
> 执行顺序：① 需求定义 → ② 构造搜索词 → ③ `web_search` → ④ `web_fetch`（按需）→ ⑤ DataPoint 结构化；反验纪律（§6）贯穿全程。

## 1. 需求定义（query_meta）

检索前先把数据需求要素定义清楚。缺失时向用户发起询问（一次问齐，不要来回）：

1. 开始时间 / 结束时间（控制数据时效）
2. 时间精度（年/季/月/日/时/分/秒）
3. 地域（控制检索地域）
4. 地域精度（国家|城市|区县|公司|站点）
5. 指标（要检索的数据指标）
6. 单位（数据单位）
7. 统计口径（这个数怎么算出来的）
8. 来源（具体站点 / 官方|行业|商业|个人 / 原始|转载）

示例：

```json
{
  "query_meta": {
    "time_range": { "start": "2025-08-01", "end": "2025-08-31", "precision": "month" },
    "geo": { "regions": ["北京", "上海", "广州"], "precision": "city" },
    "metric": {
      "name": "二手房均价",
      "unit": "元/平方米",
      "definition": "全市住宅二手房挂牌价的算术平均值，按建筑面积计算，不含商办和公寓",
      "source_preference": ["中指研究院", "链家", "贝壳", "安居客"]
    }
  }
}
```

**为什么必须显式定义**（缺失定义会直接取错数）：

- **时效与时效精度**：对比二手房价，"上一年同期"应是 2025 年 8 月，而不是 2025 年全年平均；不同城市最新月份可能不一致（北京 8 月、广州只到 7 月），需感知并说明。配量表排雷要取最新标准（GB 2760-2024），而不是旧的 GB 2760-2014。
- **地域与地域精度**：北京/上海是直辖市、广州是省会，行政范围不同；"四川"与"成都"的检索结果大相径庭。
- **单位**：可能是"元/平方米"也可能是"万元/平方米"，量纲不一致需先换算再比较。
- **统计口径**：挂牌价 vs 成交价、住宅 vs 含商办公寓、建筑面积 vs 套内面积、算术平均 vs 中位数 vs 加权平均，直接决定数值是否可比。
- **来源**：优先官方/行业/头部机构；二手科普文章只作辅助。

## 2. 构造搜索词

由 query_meta 构造搜索词：**时间 × 地域 × 指标 × 口径 × 单位 × 来源** 逐维展开成多条独立查询，逐条检索（不要合并成一条大而全的查询）。

上例构造结果：

```text
["2025年8月", "北京", "二手房挂牌均价", "住宅", "元/平方米", "中指研究院", "链家", "贝壳", "安居客"]
["2025年8月", "上海", "二手房挂牌均价", "住宅", "元/平方米", "中指研究院", "链家", "贝壳", "安居客"]
["2025年8月", "广州", "二手房挂牌均价", "住宅", "元/平方米", "中指研究院", "链家", "贝壳", "安居客"]
```

## 3. 调用 web_search

对每组搜索词调用 `web_search(query=..., max_results=...)`，结果带 `<web source=url>` 来源标记。要点：

- 优先采信来源偏好列表（`query_meta.metric.source_preference`）中的站点；
- 时效优先：结果日期须落在 `time_range` 内（落在期外时标注实际数据所属期）；
- 记录每条结果的 url（后续 `web_fetch` 与反验用）。

## 4. 调用 web_fetch（按需）

`web_search` 摘要不足以定值、或需核实原文表格/口径时，用 `web_fetch(url=...)` 抓取整页。要点：

- 只抓 source_preference 命中或权威页面，避免抓聚合转载；
- 正文超长会落盘到 `workspace/.artifacts/`，用 `read_file` 读回关键段落；
- 抓回 PDF/表格等文件时，用 `read_file` / `code_interpreter` 提取数值。

## 5. DataPoint 结构化

检索完成后，把每个来源的数值整理为 DataPoint（缺字段回原文补查，不要脑补）：

```json
{
  "value": "62847",
  "unit": "元/平方米",
  "metric": "二手住宅挂牌均价",
  "time": { "period": "2025-08", "precision": "月" },
  "space": { "region": "北京市", "granularity": "城市" },
  "caliber": "统计口径：中指研究院监测的二手住宅挂牌均价，覆盖全市挂牌房源，算术/加权平均，不含税费及中介费",
  "source": { "url": "https://…", "authority": "行业", "primacy": "原始" },
  "evidence": "中指研究院2025年8月数据，北京二手住宅挂牌均价为62,847元/平方米"
}
```

字段要求：

- `value` 与 `unit` 分列；跨来源先用统一量纲（换算）；
- `time` / `space` 单列并注明精度（precision）与粒度（granularity）；
- `caliber` 是差异归因的关键，务必写清"这个数怎么算出来的"；
- `evidence` 保留原文原句/表格行，供反验回查。

输出：把全部 DataPoint 汇总为列表，交给 `data-verify` skill 做多源比对；若只需单点结论，直接引用 DataPoint 并附来源 URL。

## 6. 反验纪律（防幻觉）

- 回答里出现的每个 URL，必须出现在工具返回中（`web_search` / `web_fetch` / `browser`）；凭空 URL 一律拦截；
- 回答里的每个数据，必须来自工具返回或 `calculator` / `code_interpreter` 的计算结果；凭空数字一律拦截；
- 没有数据佐证的论述，须声明"基于现有证据的推断"。
