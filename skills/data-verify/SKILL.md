# data-verify：多来源数据比对与交叉验证

> 端到端真实案例（多平台房价比对：口径冲突、计算vs引用、矛盾取舍、方向性交叉验证）存档于 `references/housing-example.md`，可 `read_skill data-verify references/housing-example.md` 深读。

## 1. DataPoint：先结构化，再比较

从每个来源提取的数据先整理为 DataPoint（在思考/草稿中按此结构逐字段填写，缺字段就回原文补查）：

```json
{
  "value": "61.9",
  "unit": "亿元",
  "metric": "季度营收",
  "time": { "period": "2026-Q2", "precision": "年|季|月|日|实时" },
  "space": { "region": "某公司（合并报表）", "granularity": "国家|城市|区县|公司|站点…" },
  "caliber": "统计口径：这个数怎么算出来的（按领域见下方要点）",
  "source": { "url": "https://…", "authority": "官方|行业|商业|个人", "primacy": "原始|转载" },
  "evidence": "原文中的原句/表格行（供反验回查）"
}
```

要点：
- 数值与单位分列；时间、空间单列并注明精度与粒度；
- `caliber`（口径）是差异归因的关键——同名指标在不同平台口径常常不同。常见口径维度（按领域举例，不限于此）：
  - 房产/商品：挂牌价 / 成交价 / 网签备案价 / 价格指数；
  - 财务：GAAP / Non-GAAP、调整前 / 调整后、静态 / TTM、合并 / 分部；
  - 宏观：名义 / 实际、初值 / 修正值、同比 / 环比；
  - 通用：全量 / 抽样、含税 / 不含税、算术平均 / 加权平均（按什么加权）。
- `evidence` 保留原文片段，反验时可回查。

## 2. 口径对齐（关键前置——不可跳过）

在执行任何数值比较或计算之前，必须完成口径对齐检查：

1. **列出所有 DataPoint 的口径**：对参与最终答复的每个数值，标注其口径标签（用该领域惯用名命名，见 §1 要点）；
2. **判定口径一致性**：
   - ✅ 同口径：可直接比较和计算（最稳的是同一来源、同一口径的不同期对比）；
   - ❌ 不同口径：绝对值和增跌幅**不得混在同一列或同一公式**中；
3. **口径不一致时的处理**（按优先级）：
   - **最优**：补查同口径的去年同期/上期数据，在同一口径下计算增跌幅；
   - **次优**：用另一口径的权威已公布数据替代，但必须在答复中明确写出：
     > 「A 指标（口径一）的同比暂缺，采用 B 机构已公布的 C 指标同比 X% 替代（口径一 vs 口径二，两者不可直接等同）。」
   - **最差（禁止）**：把不同口径的数值和增跌幅混入同一行/同一列，不做任何说明。

4. **最终答复表格规范**：
   - 每个数值列必须标注口径来源；
   - 若不同列口径不同，须在表头或附注中逐列说明；
   - 绝对值列和增跌幅列来自不同口径时，至少用**附注行**或**口径说明段落**明确标注；
   - 由反推/推算得到的数值列，列名必须含「反推」「推算」或「估算」字样，且表下必须附声明：
     > 「表中"反推/估算"列为根据已公布增跌幅反推的近似值，仅供参考，非 ×× 直接发布的绝对值。」

## 3. 计算验证（任务要求计算时必须遵守）

当任务要求得出数值结论——出现「计算」「算出」「求」「推导」，或 calculate / compute / derive / work out 等表述——按三级处理，**计算与引用必须严格区分**：

1. **最优——实际计算**：若能获取本期值与同期值（同口径），则展示计算过程：
   > 增跌幅 = (本期值 - 同期值) / 同期值 × 100%
   > 例：(96 - 120) / 120 = -20%

2. **次优——引用发布值并声明**：无法获取同期同口径原始数据、只能采用来源已公布的同比/环比时，必须在答复中明确声明其为**引用值（非自行计算）**，并展示反推自洽验算：
   > 「因缺少同期同口径原始数据，增跌幅采用 ×× 已公布值（**引用，非自行计算**），已反推验证算术自洽：本期值 / (1 + 同比) ≈ 同期值。」
   >
   > 若连发布值都没有、须换口径替代时，按 §2.3 次优模板写明替代声明。

3. **禁止行为**：
   - ❌ 任务要求"计算"但答复中无任何计算过程或公式，也无引用声明；
   - ❌ 把来源已公布的增跌幅直接填入表格，让用户误以为是同口径计算的结果；
   - ❌ 将引用的发布值表述为"计算得出"——表述必须是「采用××已公布值（引用），已验证算术自洽」；
   - ❌ 反推得到的数值不声明推导性质（见 §2.4 表格规范）。

## 4. 比对四步法

1. **可比性判定**：逐对检查 时间（同周期？）→ 空间（同范围？）→ 指标（同名同义？）→ 口径（定义一致？）→ 来源（是否只是同一数据的互相转载？）。不可比就先换查询词、用检索/抓取类工具（web_search / web_fetch / browser 等）补齐同口径数据，不要硬比。
2. **差异计算**：绝对差与相对差（%）；量纲不一致先换算再比较。
3. **差异归因**：按 口径 → 时间窗 → 空间粒度 → 统计时点 → 来源质量 的顺序解释差异；能归因的写明归因，不能归因的明确列为矛盾点。
4. **结论输出**：给出采信值（或区间）与置信级别，逐条附来源 URL；矛盾未决时并列呈现两方数据并说明取舍理由，**不得只列一个数字忽略矛盾来源**。列出 ≥2 个独立来源做交叉验证时，**必须输出方向性结论**——明确比较各来源对同一指标的涨跌方向与相对排序是否一致，并说明对结论可靠性的影响：
   > 「交叉验证结论：来源 A（甲 -8.8% > 乙 -7.6% > 丙 -5.0%）与来源 B（甲 -4.5% > 乙 -2.9% > 丙 -2.0%）方向一致、排序一致（甲跌幅最大、丙最抗跌），结论可靠性增强；绝对值差异源于口径不同（口径一 vs 口径二），属预期。」

   方向矛盾时：降低置信级别、并列呈现双方数据并说明分歧，不得给出单边结论。只写"绝对值不同属正常"**不算**完成交叉验证。

## 5. 数据矛盾处理

当同一指标多个来源数据差异显著——**超出口径、样本范围、时间窗可解释的范围**时（经验参考：相对差 >20%，但须按指标波动性调整——汇率/利率等低波动指标差异 1% 已属矛盾，高波动指标可适当放宽）：

1. **识别矛盾**：列出所有来源的值、口径、时间、样本说明；
2. **归因差异**：按 APTC 框架评估来源可信度，分析差异原因（口径 / 样本范围 / 时间窗 / 加权方式）；
3. **选择主口径**：明确写出采信哪个来源作为主口径，附理由（如「采信来源 X：样本覆盖完整、更新至当期、数据原始」）；
4. **并列呈现**：在最终答复中，主口径数据放入主表，其他来源数据放入附注或对照表，**不得只列一个忽略其余**。

## 6. 来源置信度评估（APTC）

对每个来源按四维打分（高/中/低），冲突时优先采信高置信来源：

| 维度 | 判断标准 |
|---|---|
| **权威性 Authority** | 官方统计机构 / 国家级研究机构 / 行业公认头部机构 ＞ 主流媒体 ＞ 自媒体/个人 |
| **原始性 Primacy** | 原始采集 ＞ 二次转载/聚合；转载要追原始出处（能定位就用抓取工具核实原始页） |
| **透明度 Transparency** | 是否明确说明采集方法、样本量、口径定义与统计时点 |
| **一致性 Consistency** | 与其他**独立**来源交叉验证的结果；≥2 个独立来源一致才可标高 |

## 7. 反验纪律（贯穿执行全程）

- **先查证每个数字**（进 DataPoint），**再反验每条结论**（回查原文或找第二独立来源确认）；
- 空间与时间逻辑：任何比较之前，先确认双方的时间窗与空间范围完全对齐，未对齐的数字不进同一张对比表；
- 交叉验证不需要专用工具：用检索/抓取类工具（web_search / web_fetch / browser 等）取独立来源，比对走上述四步法；
- 最终答复中的每个数据都标注来源 URL，无法溯源的表述标注「未溯源」。
